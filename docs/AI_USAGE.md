# AI 활용 및 검증 기록

작업일: 2026-11-09 (한국 시간)

## 사용자 요청

이 문서는 실제 대화의 요청을 정리한 작업 기록입니다.

- 기존 LEC15 코드에서 로고 → 타이틀 → 플레이를 연결한다.
- 타이틀의 Space로 플레이를 시작하고, 플레이의 Esc로 타이틀에 돌아간다.
- P로 정지·재개하고 기존 게임 상태를 유지한다.
- Drill 13 과제 이미지에 맞춰 아이템 모드를 구현하고 `drill-13` 새 저장소로 만든다.
- 아이템 모드에서 0=공 없음, 1=작은 공, 2=큰 공을 선택한다.
- 오늘 작성한 기존 기능 커밋도 새 저장소로 가져온다.

## 진행한 작업

1. 기존 게임 폴더의 커밋 이력을 추출했다. 타이틀·플레이·P 기능의 작성자와 날짜,
   메시지를 보존했고, 새 폴더 구조에 따른 해시 변경을 HISTORY.md에 기록했다.
2. 독립 가상환경, 실행 설정, 패키지 목록과 저장소 제외 항목을 준비했다.
3. 캐릭터에 선택 아이템을 두고, 공 없음에서는 발사하지 않도록 했다.
   작은 공과 큰 공은 각각 제공된 `ball21x21.png`, `ball41x41.png`를 사용한다.
4. I로 아이템 모드를 올리고, 숫자를 고르면 기존 플레이로 돌아가도록 구현했다.
   I 또는 Esc 취소 시에는 기존 선택을 유지한다.
5. 정지 및 아이템 모드에서 게임 업데이트를 멈추고, 복귀 시 수면 타이머와 방향키를 보정했다.
6. 기능별 실제 변경을 나눠 커밋하고 아래 검증을 수행했다.

## 확인 결과

- `python -m unittest discover -s tests -v`: 테스트 9개 통과.
- 실제 게임 루프에서 로고 → 타이틀 → 플레이 → 아이템 선택 → P 정지·재개 → 타이틀 → 종료 확인.
- 실행 위치를 상위 폴더로 바꿔도 이미지와 폰트를 정상적으로 읽는 것 확인.
- 아이템 화면을 SDL 렌더러에서 캡처하고 글자·그림·선택 안내가 잘리는 부분이 없는지 확인.
- PNG 파일명과 달리 테두리를 포함한 실제 파일 크기는 작은 공 23×23, 큰 공 43×43이다.
  테스트는 실제 제공 이미지의 크기를 사용한다.
- 공 종류를 바꿔도 이전에 발사한 공의 크기와 방향이 변하지 않는 것 확인.

실제 코드와 검증 결과를 기록했으며, 실행하지 않은 테스트나 수동 조작을 수행했다고 적지 않았다.
